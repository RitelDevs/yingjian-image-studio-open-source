# 1.5 发布与上线准备

版本：1.5.0。整理日期：2026-10-26。

## 发布范围

包括当前工作台、风格市场、会话管理、账号连接和后台协议；不包括中转后台源码、生产用户数据、付费模型凭据、服务器专用运维脚本或 Git 历史。

本轮 GitHub 发布采用新的公开仓库。既有组织私有仓库、其他仓库及其历史/设置均不变更。

## 本地制作发布产物

```sh
npm ci
npm run check
npm run build:published
npm run release:package
```

产物位于 `release/v1.5.0/`：

- `source/`：允许公开的源码；在干净目录 `npm ci && npm run check` 可独立验证。
- `deployment/`：编译好的 `dist/`、`dist-server/`、部署模板、文档及第三方通知。
- `yingjian-1.5.0-source.tar.gz` 与 `yingjian-1.5.0-deployment.tar.gz`。
- `SHA256SUMS`、`RELEASE_MANIFEST.json`：压缩包及部署文件哈希。

打包脚本只按允许清单复制文件，并检查私钥、常见 Token 和危险运行文件。它不读取 `.env` 或账号数据库，也不上传/部署任何内容。

## 上线操作顺序

1. 在独立演示环境验证该构建，不使用真实用户账号测试。
2. 在现有实例确认没有仍在进行或排队的任务，备份持久化数据、私有 `.env` 和反向代理配置。
3. 把部署压缩包上传到新的版本目录；校验 SHA-256。服务器不安装构建依赖、不运行 Vite/esbuild。
4. 配置 `deploy/production.env.example` 对应的私有 `.env`、可信上游、模型别名、10 并发和 HTTPS Origin。正式模式必须关闭 DEMO。
5. 持久化数据目录保持独立。确认容器运行用户具有目录读写权限，启动 `deploy/compose.example.yaml` 或直接运行 `node dist-server/index.mjs`。
6. 先检查 `/api/health` 的版本为 `1.5.0`，检查 `/api/config` 演示关闭，以及未登录读取 `/api/threads` 为 401。
7. 配置/验证 HTTPS 和可选 SSO 桥接。使用获准的专用测试账号检查登录、余额/分组、会话隔离、原图/编辑图、上传和回传。
8. 真实对话/生图会计费，须在运营方明确授权的受控验收中执行；核对使用的是该测试用户本人的分组 Key 和余额。
9. 验证通过后再切换生产入口。只保留明确需要的回滚版本，不顺手删除业务数据。

## 验证记录

最终计数与产物哈希写在随版本提供的 `docs/VALIDATION_1.5.md`。Node 测试涵盖账号隔离、API、队列、协议、风格与编辑核心；浏览器模拟涵盖左右分屏、独立缩放拖动、裁剪撤销、账号/文档来源恢复和参考图回传。

本轮没有进行生产部署、真实付费请求或 200 在线用户压力测试。200 人同时在线不等于同时 200 个模型请求；任务并发上限是 10，实际吞吐还取决于上游速度、限流与服务器容量。

## 回滚

保留上一版代码与本次上线前的数据库备份。失败时先暂停入口和新任务，再恢复上一版服务/路由。涉及数据库结构变化时依据备份恢复，不假定旧代码可以安全忽略全部新字段。本版本的会话改名辅助表仍由存储初始化自动建立。

浏览器编辑草稿保存在当前设备 IndexedDB；它不是服务端七天历史的备份。离开设备前需要提交到会话或导出图片。
